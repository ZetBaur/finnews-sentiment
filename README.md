# Классификация тональности финансовых новостей

Учебный проект: по короткой финансовой фразе определить тональность (positive / negative / neutral).

## Данные

Financial PhraseBank, файл `Sentences_50Agree.txt` (формат `текст@класс`, кодировка latin-1). Загрузка: `load_data.py`.

## День 1. Первичный анализ (`eda.py`)

Результаты запуска:

- Размер: 4846 строк, 2 колонки (`text`, `sentiment`), обе строковые.
- Пропусков нет (0 в обеих колонках).
- Классы: neutral 2879 (59,4%), positive 1363 (28,1%), negative 604 (12,5%).
- Дубликаты текстов: 8 (около 0,2%).
- Длина текста: в среднем 128 символов (23 слова), медиана 119 символов (21 слово), минимум 9 символов (2 слова), максимум 315 символов (81 слово).

Наблюдения:

1. Классы несбалансированы: нейтральных почти в 5 раз больше, чем негативных. Значит, accuracy (доля верных ответов) будет обманчивой: модель, которая всегда отвечает neutral, получит около 59%. Нужны precision, recall, F1 по каждому классу.
2. Пропусков нет, чистить пустые тексты не нужно.
3. Тексты короткие (одно предложение), разброс длины умеренный. Обрезать или отбрасывать длинные не требуется.
4. В примерах знаки препинания отделены пробелами (`company 's`, `, `, `20 % -40 %`). Похоже, тексты уже разбиты на токены.
5. Часть примеров спорная: класс не всегда очевиден по тексту (например, фраза про индекс FTSE в классе negative). Версия файла `50Agree` включает фразы, где разметчики согласились лишь на 50%.

Решение: 8 дубликатов удалить на этапе очистки (день 2), чтобы одна фраза не попала и в обучение, и в тест. Не проверено: совпадают ли классы у дубликатов; графики не построены.

## День 2. Очистка и подготовка (`src/finnews/preprocess.py`)

Запуск: `python -m finnews.preprocess` (пример «до / после» и сводка в логе). Тесты: `pytest`. Настройки (путь к данным, минимальная длина текста, соответствие классов числам) лежат в `configs/config.json`.

`clean_text(text)` чистит один текст: HTML-символы (`&amp;` → `&`), юникод-нормализация (NFKC, например неразрывный пробел → обычный), нижний регистр, удаление ссылок, схлопывание пробелов. Не-строки (`None`, `NaN`) дают пустую строку. Цифры, `%` и знаки препинания остаются: для финансовых новостей они несут смысл.

`preprocess(df)` чистит таблицу и возвращает новую (исходная не меняется): отбрасывает пустые и короткие тексты (меньше `min_text_length`), неизвестные классы, тексты с конфликтом классов (один текст, разные метки: убираем все копии) и дубликаты; добавляет колонку `label` (negative 0, neutral 1, positive 2). Каждый шаг пишет в лог, сколько строк отброшено.

Результат на Financial PhraseBank: 4846 → 4836 строк (4 с конфликтом классов, 6 дубликатов, пустых и неизвестных классов 0).

Ограничения: в исходном файле есть следы неверной кодировки (около 30 строк, например `+Ârbindelsen`, `-¦ s`, `+ó  x201a` вместо знака евро). Мы их не исправляем. Токены вида `company 's` остаются как есть: тексты уже разделены пробелами.

## День 3. Baseline (`src/finnews/baseline.py`)

Запуск: `python -m finnews.baseline`. Тесты: `pytest`. Настройки (`test_size`, `random_state`, `max_iter`, пути `metrics_path` и `model_path`) лежат в `configs/config.json`.

Процесс: очищенные данные → деление на train и test (20%, `stratify` по классу, `random_state` 42) → `Pipeline` из TF-IDF и Logistic Regression (TF-IDF учится только на train, утечки нет) → метрики на test → сохранение в `reports/baseline_metrics.json` и `models/baseline.joblib` (модель не коммитится).

Результат (train 3868, test 968): accuracy 0.770, macro F1 0.696. Правило «всегда neutral» даёт accuracy 0.594 и F1 0.248. По классам: negative P 0.84 / R 0.48 / F1 0.61, neutral 0.77 / 0.94 / 0.84, positive 0.76 / 0.55 / 0.64.

Вывод: модель часто принимает negative (46 из 121) и positive (118 из 272) за neutral. Точка отсчёта для дня 4: macro F1 0.696.

Проверка утечки (`experiments/leak_demo.py`): если учить TF-IDF на всех данных, в словарь попадают 1118 слов из test (8942 → 10060), но метрики почти не меняются (accuracy 0.768, F1 0.683). Всё равно учим только на train.

Теория с графиками: `theory_*.py` (запуск из корня проекта), картинки в `reports/theory/`.

## День 4. Улучшение baseline (`src/finnews/improve.py`)

Запуск: `python -m finnews.improve`. Варианты лежат в `configs/config.json`, блок `experiments`; результат пишется в `reports/improve_metrics.json`.

Как сравниваем: те же train/test и `random_state`, что у baseline. Вариант оценивается кросс-валидацией на train (5 частей, TF-IDF внутри `Pipeline`, утечки нет). Лучший выбираем по CV F1, test используем только как финальную проверку (иначе настройки подгоняются под test).

| Вариант | CV F1 | test accuracy | test F1 | признаков |
|---|---|---|---|---|
| baseline (LogReg, C=1) | 0.652 ± 0.016 | 0.770 | 0.696 | 8942 |
| n-граммы (1, 2) | 0.625 ± 0.024 | 0.750 | 0.652 | 49700 |
| LogReg C=10 | 0.703 ± 0.015 | 0.767 | 0.708 | 8942 |
| LogReg C=100 | 0.698 ± 0.017 | 0.759 | 0.705 | 8942 |
| LinearSVC C=0.5 | 0.707 ± 0.012 | 0.775 | 0.715 | 8942 |
| LinearSVC C=1 | 0.709 ± 0.017 | 0.768 | 0.709 | 8942 |

Что помогло: больший `C` и замена на LinearSVC (CV F1 с 0.652 до 0.70–0.71, разница больше разброса ±0.015). Что не помогло: n-граммы (1, 2) с Logistic Regression C=1 (CV 0.625, test F1 0.652; словарь вырос в 5,5 раза). Проверка `experiments/ngram_mindf.py` с LinearSVC: те же n-граммы дают CV F1 0.706–0.714 при `min_df` 1/2/3/5, то есть не хуже 1-грамм (0.709): объяснение «слишком много редких пар» не подтвердилось, причина падения у Logistic Regression не доказана.

Выбор: LinearSVC C=1 (самый высокий CV F1 0.709 и самый быстрый). Между вариантами с `C` 10+ и LinearSVC разница внутри разброса, поэтому выбор по простоте и скорости, а не по «победе» в цифрах.

Теория с графиками: `theory_ngrams.py`, `theory_c.py`, `theory_cv.py`, картинки в `reports/theory/`. Замечание: `theory_c.py` строит график по test только для иллюстрации; выбор `C` делался по CV.

Правило сравнения: улучшением считаем разницу больше разброса CV (около ±0.02); иначе берём более простой вариант. Одна цифра на test (968 строк) случайна и не доказательство.

## День 5. Анализ ошибок (`src/finnews/errors.py`)

Запуск: `python -m finnews.errors` (модель LinearSVC C=1, ключ `best_experiment` в конфиге). Результат: `reports/errors.csv` (все ошибки с уверенностью модели `margin`), `reports/confusion_matrix.png`, счётчики и примеры в логе.

Итог на test: 225 ошибок из 968 (23.2%).

| Настоящий → ответ | Ошибок |
|---|---|
| positive → neutral | 92 |
| neutral → positive | 52 |
| negative → neutral | 39 |
| neutral → negative | 18 |
| negative → positive | 15 |
| positive → negative | 9 |

Основные слабые места:
1. **Ответ neutral вместо positive/negative (131 из 225).** В предложении нет слов-подсказок (например, «получил большую часть контракта»), а neutral самый частый класс (59%), поэтому при слабом сигнале модель выбирает его.
2. **Слова вместо смысла.** «Loss after taxes … compared to a loss of 2.6 mn» (убыток сократился, размечено positive) модель считает negative из-за слова «loss». Сравнение чисел и направление изменения она не видит.
3. **Часть уверенных ошибок похожа на спорную разметку** (например, описание компании размечено positive). Не проверено, нужна ручная проверка выборки.

Проверка гипотезы 2 (`experiments/shuffle_words.py`): если перемешать слова в предложениях test, accuracy 0.768 и macro F1 0.709 не меняются совсем. Модель не использует порядок слов, только их набор.

Что улучшать дальше: модель, которая понимает контекст (трансформеры, ДЗ 5); проверить разметку самых уверенных ошибок; при необходимости веса классов (`class_weight`) против перекоса к neutral.

Теория с графиком: `theory_errors.py`, картинка `reports/theory/errors.png`.
